سورس واقعی با Cursor SDK بررسی شد؛ برنامه و PostgreSQL خصوصی در تیم لیارا ساخته شدند، تنظیمات به‌صورت امن متصل شدند و ثبت سفارش واقعی آزمایش شد. این گزارش موفقیت‌ها، شکست‌ها و محدودیت‌ها را از هم جدا می‌کند.

برنامه و دیتابیس آزمایشی حذف شدند. بررسی مجدد در 14:30 UTC، صفر برنامه و صفر دیتابیس را در حساب شخصی و تیم لیارا تأیید کرد. موجودی تیم پس از حدود ۳۵ دقیقه همچنان ۱٬۹۹۸٬۸۵۴٫۲ تومان بود. دو شبکهٔ بدون عضو باقی‌اند: درخواست حذف هر دو HTTP 404 داد و قابلیت حذف پشتیبانی‌شده پیدا نشد. ثابت‌ماندن اعتبار، مشاهدهٔ مالی است و جای فاکتور نهایی را نمی‌گیرد.

حساب و موجودیتأیید شدتیم «لیارا» در API مالی ۲٬۰۰۰٬۰۰۰ تومان اعتبار داشت؛ موجودی شخصی حدود ۵ تومان بود. انتخاب تیم با teamID اصلاح شد.
تحلیل کد و Cursor SDKتأیید شد7 فایل واقعی، PostgreSQL، نام متغیرها و Docker تشخیص داده شدند. کرسر ابزار پروژه و حافظه را واقعاً فراخوانی کرد.
ساخت زیرساخت خصوصیتأیید شدیک برنامه و یک PostgreSQL 16.14 روی شبکهٔ مشترک ساخته شدند. شبکهٔ عمومی دیتابیس غیرفعال است.
تنظیمات محرمانهتأیید شدDATABASE_URL خودکار ساخته و همراه TEST_CONTROL_TOKEN در برنامه تنظیم شد. مقادیر در این گزارش و گفتگو نیستند.
استقرار نسخهٔ دقیقتأیید شدنسخهٔ 6ada0c9812fe5042a6a98312 به READY رسید؛ خطای MIME اصلاح شد و ادامهٔ انتشار هیچ منبع تکراری نساخت.
سلامت و عملیات کسب‌وکارتأیید شدهر دو endpoint پاسخ ۲۰۰ دادند. تست کسب‌وکار یک سفارش را در تراکنش نوشت، خواند و ROLLBACK کرد؛ دو بررسی موفق انجام شد.
سفارش واقعی و ماندگاریتأیید شدسفارش با HTTP 201 در PostgreSQL ثبت شد؛ پس از اختلال هم همان شناسه در دیتابیس وجود داشت. این آزمون شامل پرداخت واقعی نیست.
کشف مستقل اختلالتأیید شدبدون پیام کاربر، worker با سه شکست متوالیِ یک‌دقیقه‌ای، رخداد c2497e4f را در 13:31:45 UTC ایجاد کرد.
تشخیص و کنترل اختیاراتبخشی تأیید شدبه‌دلیل قطع API، لاگ و متریک کامل در دسترس نبود. کرسر علت قطعی نساخت و ری‌استارت بی‌پشتوانه پیشنهاد نکرد؛ رخداد به بررسی بیشتر رفت.
تأیید بهبودتأیید شدپس از برداشتن اختلال توسط اپراتور، دو بررسی موفق انجام شد و رخداد RESOLVED شد. این اصلاح، ری‌استارت خودکار نبود.
ری‌استارت و ماندگاری بعد از آنتأیید شدتغییر زمان شروع پردازه و باقی‌ماندن سفارش تأیید شد.
حذف منابع آزمایشیتأیید شدحذف برنامه و دیتابیس با پاسخ موفق و فهرست خالی منابع تأیید شد. شبکه‌های خالی خصوصی در تاریخچه باقی‌اند.
تست خودکار و buildتأیید شد۵۶ تست خودکار موفق و صفر شکست؛ TypeScript و Vite build موفق بودند.
بررسی مجدد پاک‌سازیتأیید شددر 14:30 UTC حساب شخصی و تیم لیارا دوباره خوانده شدند: صفر برنامه و صفر دیتابیس. هر دو شبکه projectCount=0 و databaseCount=0 دارند. اعتبار تیم پس از حدود ۳۵ دقیقه تغییری نداشت.
حذف شبکه‌های خالیدر دسترس نبوددرخواست DELETE /v1/networks/{id} برای هر دو شبکهٔ مشخصِ تست HTTP 404 داد؛ خواندن مجدد باقی‌ماندن آن‌ها را نشان داد. در مستندات، CLI و کد عمومی پنل قابلیت حذف پیدا نشد؛ حذف موفق ادعا نمی‌شود.
دامنه، DNS و HTTPSبخشی بررسی شددر آزمون ابری قبلی، فقط HTTPS پیش‌فرض liara.run استفاده شد؛ دامنهٔ شخصی زنده آزمایش نشد. اکنون جریان DNS لیارا، تغییر NS توسط کاربر، ثبت خودکار رکوردهای اتصال/مالکیت/ACME و درخواست SSL پیاده‌سازی و با پاسخ‌های کنترل‌شده تست شده است. این به‌معنای صدور واقعی گواهی برای دامنهٔ شخصی نیست.
جریان جدید DNS لیاراتست کنترل‌شده۱۶ تست دامنه و ۷۲ تست کل پروژه موفق شدند. خواندن API واقعی DNS با HTTP 200 تأیید شد؛ هیچ zone واقعی، دامنه یا منبع هزینه‌دار جدیدی ساخته نشد. کاربر فقط NS را در ثبت‌کننده تغییر می‌دهد و ایجنت پس از بررسی مستقل آن، رکوردها و SSL را پیگیری می‌کند.

اصلاحاتی که از آزمون به محصول برگشت

اصلاح 01

حساب درست، پیش از هزینه

پارامتر رسمی teamID جایگزین هدر نادرست شد. انتخاب حساب همراه موجودی وارد تنظیمات و راه‌اندازی شد؛ پاسخ انتخاب تیم دوباره تأیید می‌شود.

اصلاح 02

هزینهٔ قابل‌فهم و ساعتی

نرخ ساعتی در تأیید هزینه اول دیده می‌شود؛ برآورد روزانه و ۳۰روزه کنار آن است. رقم ماهانه، پیش‌پرداخت معرفی نمی‌شود.

اصلاح 03

آپلود سازگار با API واقعی

فایل tar.gz با MIME صحیح application/gzip ارسال می‌شود. این خطا فقط در یکپارچه‌سازی واقعی دیده شد.

اصلاح 04

ادامه بدون ساخت تکراری

شکست قطعی پیش از ایجاد نسخه، با کنترل سورس، تنظیمات، حساب و نبود انتشار قبلی، پیشنهاد تازه برای ادامهٔ انتشار می‌سازد؛ مرحله‌های ساخت تکرار نمی‌شوند.

اصلاح 05

پیگیری نسخه و لاگ ساخت

زمان انتظار افزایش یافت؛ نتیجهٔ همان نسخه را می‌توان بدون انتشار مجدد بررسی کرد. مسیر جدید v2 لاگ برنامه و خواندن لاگ ساخت اضافه شد.

اصلاح 06

تحلیل امن‌تر و کوتاه‌تر

تحلیل پروژه فقط ابزارهای read-only دارد. توضیح کوتاه و جمع‌شونده است؛ HTML مدل اجرا نمی‌شود. خطای یک منبع شواهد کل تحلیل را متوقف نمی‌کند.

اصلاح 07

خطای شبکه به‌جای حدس

خواندن API در خطای انتقال یک بار تکرار می‌شود؛ نتیجهٔ نامشخص تغییر تکرار نمی‌شود. فقط در شکست قطعی DNS، resolver ایرانی برای نام عمومی API استفاده می‌شود؛ گواهی HTTPS همچنان با نام اصلی اعتبارسنجی می‌شود و DNS ویندوز تغییر نمی‌کند.

محدودیت‌ها و کار باقی‌مانده

این یک آزمون یکپارچه‌سازی روی فروشگاه آزمایشی است، نه گواهی آمادگی عمومی برای همهٔ پروژه‌ها. پرداخت بانکی، بازگردانی ابری دیتابیس و مهاجرت دلخواه پروژه‌ها در این آزمون انجام نشد. Vault محلی جایگزین KMS چندکاربره نیست. DNS لیارا در میانهٔ تست از دو resolver مستقل SERVFAIL داشت. اطلاعات شخصی و پرداخت واقعی در فروشگاه دریافت نشد. Docker محلی به‌علت فشار منابع لپ‌تاپ، مبنای ادعای موفقیت نیست. در آزمون ابری قبلی دامنهٔ اختصاصی بررسی نشد. جریان جدید DNS لیارا اکنون پیاده‌سازی شده و تست کنترل‌شده دارد، ولی دامنهٔ شخصی زنده و صدور واقعی گواهی هنوز آزمایش نشده‌اند.
