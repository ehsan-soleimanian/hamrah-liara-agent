# دامنهٔ شخصی با DNS لیارا

مسیر اصلی محصول اکنون DNS خود لیارا است. کاربر دامنهٔ خریداری‌شده را می‌دهد؛ کلید جداگانه‌ای برای DNS لازم نیست. از کلید لیارا و همان حساب شخصی/تیم استفاده می‌شود.

## جریان ساده

1. فقط پیشنهاد خواندنی ساخته می‌شود. نام دامنه استاندارد و دامنهٔ اصلی با Public Suffix List تشخیص داده می‌شود؛ انتشار باید موفق و همچنان فعال باشد.
2. پس از تأیید کاربر، zone رایگان DNS در حساب لیارا آماده می‌شود و دامنه به همان برنامه متصل می‌شود.
3. نیم‌سرورهای واقعی از پاسخ API همان zone دریافت و نمایش داده می‌شوند؛ در محیط واقعی نام NS حدس زده یا ثابت نوشته نمی‌شود.
4. کاربر فقط NSها را در ثبت‌کنندهٔ دامنه، مثلاً ایرنیک، جایگزین می‌کند. اگر سرویس قدیمی دارد، ابتدا باید رکوردهایش را منتقل کرده باشد. اجازهٔ ثبت رکوردهای مشخص اتصال و SSL تا ۲۴ ساعت با تأیید دقیق ثبت می‌شود.
5. ایجنت هم وضعیت ACTIVE در سرویس DNS لیارا و هم نتیجهٔ عمومی NS را مستقل بررسی می‌کند. اعلام «انجام دادم» به‌تنهایی تأیید فنی نیست.
6. پس از تأیید NS، رکورد مسیر سایت (ALIAS برای apex، CNAME برای زیردامنه)، TXT مالکیت و CNAME چالش ACME ثبت می‌شوند. مقصد و کد مالکیت از جزئیات واقعی دامنه در لیارا می‌آیند.
7. بعد از تأیید هر سه رکورد توسط PaaS لیارا، درخواست گواهی SSL ثبت می‌شود. SSL رایگان است و تمدید آن را لیارا انجام می‌دهد.
8. دریافت گواهی کافی نیست: نام و زنجیرهٔ گواهی، تاریخ انقضا، پاسخ موفق HTTPS و انتقال HTTP به HTTPS جداگانه بررسی و گزارش می‌شوند.

تمام مراحل، تأییدها، مقادیر پیش و پس از تغییر، نتایج و خطاها در SQLite و audit زنجیره‌شده باقی می‌مانند. get_domains و حافظهٔ Cursor وضعیت و شواهد را می‌خوانند؛ request_domain_connection تنها درخواست تأیید مسیر لیارا را می‌سازد و اختیار تأیید یا اجرای دلخواه ندارد.

## APIها و دامنهٔ اختیارات

PaaS رسمی: https://api.liara.ir
- GET و POST /v1/domains
- GET /v1/domains/{name}
- GET /v1/domains/{id}/check
- POST /v1/domains/provision-ssl-certs با نام دامنه، نه شناسه

DNS رسمی: https://dns-service.liara.ir/api/v1
- GET و POST /zones
- GET /zones/{zoneName}
- PUT /zones/{zoneName}/check
- GET و POST /zones/{zoneName}/dns-records
- DELETE /zones/{zoneName}/dns-records/{recordId} فقط برای رکورد قبلی مشخص و تأییدشده
- بدنهٔ رکورد شامل type، name، ttl و contents است؛ TXT از text و ALIAS/CNAME از host استفاده می‌کنند.
- احراز هویت Bearer و انتخاب تیم با query به نام teamID. GET /zones با حساب واقعی تیم، HTTP 200 و فهرست خالی داد؛ برای آزمون این تغییر هیچ zone زنده‌ای ساخته نشد.
- قرارداد جزئیات DNS با کد عمومی کنسول رسمی تطبیق داده شده است؛ قابلیت حدس‌زده‌شده به محصول معرفی نمی‌شود.

رابط داخلی:
- GET /api/domains?jobId=...
- POST /api/domains/plan
- POST /api/domains/:id/decision با fingerprint و approve
- POST /api/domains/:id/nameservers برای اعلام انجام مرحلهٔ ثبت‌کننده و شروع بررسی مستقل
- POST /api/domains/:id/check
- POST /api/domains/:id/cancel برای توقف پیگیری، بدون حذف رکوردهای قبلی

پیشنهادها به mode، کلید حساب، تیم، انتشار و برنامهٔ مشخص محدودند. اعتبار تأیید ۱۰ دقیقه است. تغییر رکورد از زمان پیش‌نمایش تأیید تازه می‌خواهد. رکوردهای MX، NS، SOA، CAA و TXTهای سرویس‌های دیگر حذف نمی‌شوند. ALIAS دامنهٔ اصلی با NS/SOA/MX/TXT هم‌زیستی دارد؛ آن‌ها تعارض رکورد وب محسوب نمی‌شوند.

## پیگیری و خطا

worker مستقل از چت، در زمان روشن‌بودن سرور وضعیت NS/DNS/SSL را حدود هر دقیقه بررسی می‌کند. اختیار راه‌اندازی پس از ۲۴ ساعت پایان می‌یابد؛ ادامه نیاز به پیشنهاد تازه دارد. دامنهٔ فعال هر شش ساعت دوباره بررسی می‌شود؛ اعتبار کمتر از ۱۴ روز هشدار ثبت می‌کند.

پیش از نوشتن intent ذخیره می‌شود. بسته‌شدن برنامه وسط تغییر یا پاسخ نامشخص، به توقف برای بررسی منجر می‌شود. درخواست SSL نامشخص خودکار تکرار نمی‌شود. تغییر نیمه‌کارهٔ DNS rollback مخرب ندارد؛ مقادیر قبلی برای بررسی و تصمیم بعدی حفظ می‌شوند. چنانچه لیارا رکوردها را از قبل درست ایجاد کرده باشد، مرحلهٔ مربوط keep است و رکورد تکراری ساخته نمی‌شود.

برای بررسی HTTPS تمام IPهای resolveشده باید عمومی باشند. اتصال به IP بررسی‌شده pin می‌شود، TLS نام دامنه را اعتبارسنجی می‌کند و redirect دنبال نمی‌شود. DNS rebinding یا هدایت به شبکهٔ داخلی مجاز نیست. محتوای صفحه به مدل داده نمی‌شود.

## محدودیت‌های روشن

- اتصال زندهٔ دامنه و صدور واقعی گواهی هنوز به دامنهٔ متعلق به کاربر و تغییر NS آن نیاز دارد؛ آزمون‌های جدید با پاسخ‌های کنترل‌شده و رابط نمایشی انجام شده‌اند. خواندن API DNS واقعی جداگانه موفق بوده است.
- تغییر NS در ایرنیک یا ثبت‌کننده، خارج از APIهای متصل است و بر عهدهٔ کاربر می‌ماند.
- تغییر NS مدیریت کل دامنه را منتقل می‌کند. کشف تمام رکوردهای ارائه‌دهندهٔ قبلی، DKIM خصوصی یا سرویس‌های ناشناخته از DNS عمومی ممکن نیست. انتقال خودکار همهٔ رکوردهای قدیمی یا DNSSEC ادعا نمی‌شود؛ کاربر باید پیش از تغییر NS از مهاجرت رکوردهای ضروری و سازگاری DS/DNSSEC مطمئن شود.
- wildcard، خرید دامنه و انتقال اتصال از برنامهٔ دیگر پشتیبانی نمی‌شوند.
- هدایت HTTP به HTTPS بررسی می‌شود اما خودکار در کد دلخواه برنامه اعمال نمی‌شود؛ API هدایت دامنه به خودش می‌تواند حلقه بسازد و برای این کار استفاده نمی‌شود.
- پاسخ صفحهٔ اصلی تضمین صحت تمام عملیات تجاری نیست؛ پایش کسب‌وکار موجود جداگانه باقی می‌ماند.
- Cloudflare و راهنمای دستی به‌عنوان گزینه‌های اختیاری حفظ شده‌اند؛ مسیر پیش‌فرض لیارا است.
