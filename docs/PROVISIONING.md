# راه‌اندازی بدون پنل زیرساخت

کاربر پروژه را معرفی می‌کند، پیشنهاد را می‌بیند، نام سایت و اطلاعات ضروری سرویس‌های خارجی را وارد می‌کند و در یک صفحهٔ جدا هزینه و مراحل را تأیید می‌کند. ساخت شبکه، برنامه، دیتابیس، اتصال تنظیمات و انتشار در همین جریان انجام می‌شود. PostgreSQL، MySQL، MongoDB و Redis در قرارداد ساخت پوشش داده شده‌اند؛ نسخه و پلن فقط از موارد قابل‌دسترسی حساب انتخاب می‌شوند.

## مرز اعتماد و تأیید

گزارش تحلیل ایستا، سورس قابل‌انتشار را به هش مشخص متصل می‌کند. پیشنهاد ساخت در SQLite فقط اطلاعات قابل‌نمایش را نگه می‌دارد. ورودی‌های محرمانه، حساب مقصد و کاتالوگ تأییدشده در Vault با AES-256-GCM نگه داشته می‌شوند. digest اطلاعات عمومی نیز در همان رکورد رمزگذاری‌شده است تا تغییر هزینه، مقصد یا نسخه در رکورد SQLite، تأیید را نامعتبر کند.

انقضا ده دقیقه است و تأیید تکراری پذیرفته نمی‌شود. پیش از ساخت و قبل از هر سرویس پولی، قیمت‌ها دوباره خوانده می‌شوند؛ تغییر پلن یا هزینه اجرای بدون تأیید تازه را متوقف می‌کند. قیمت قطعی از طرف لیارا قفل نمی‌شود؛ برآورد ۷۲۰ ساعت منابع به‌علاوهٔ امکانات است و مصرف/مالیات متغیر را تضمین نمی‌کند. اعتبار حساب لیارا مصرف می‌شود؛ هیچ درگاه انتقال وجه یا شارژ بانکی وجود ندارد.

## مراحل اجرا

1. کنترل سورس، حساب و تعرفهٔ پیشنهاد.
2. ساخت یا انتخاب شبکهٔ خصوصی مشترک.
3. ساخت برنامهٔ تازه؛ نام موجود به‌عنوان مقصد جایگزینی پذیرفته نمی‌شود. آدرس عمومی پیش‌فرض در صورت نیاز فعال می‌شود.
4. ساخت دیتابیس با publicNetwork=false؛ انتظار محدود برای آماده‌شدن؛ ثبت فوری شناسهٔ هر منبع.
5. دریافت اطلاعات اتصال فقط سمت سرور و ساخت URI با encoding رمز/نام کاربری. نام و پورت خصوصی طبق قرارداد Liara استفاده می‌شوند. MySQL بدون نام دیتابیسِ قابل‌تأیید، با نام حدسی متصل نمی‌شود.
6. دریافت env فعلی برنامهٔ تازه، ادغام با تنظیمات تأییدشده و ارسال کامل. اگر مقدار موجود خواندنی نیست یا رمزگذاری‌شده/ماسک‌شده است، برای جلوگیری از حذف یا خراب‌کردن آن توقف می‌کنیم. اتصال خودکار اسرار به متغیرهای عمومی فرانت‌اند مثل NEXT_PUBLIC و VITE ممنوع است.
7. ارسال بستهٔ سورس تأییدشده، ثبت releaseID و انتظار برای فعال‌شدن همان نسخه.
8. دو پاسخ سالم متوالی از سایت و، در صورت وجود، آزمایش مستقل کسب‌وکار با JSON شامل ok:true.

بدون مسیر مستقل کسب‌وکار، `needs_verification` ثبت می‌شود؛ انتشار و پاسخ سایت تأیید شده ولی کارکرد عملیات اصلی هنوز اثبات نشده است. پایش کاملِ مبتنی بر هر دو endpoint تا تکمیل این بخش به عنوان فعال معرفی نمی‌شود.

## حافظه و خطا

`provisionJobs` شامل مراحل، هزینه، وضعیت، اثر و شناسهٔ منابع است. مقادیر env، رمز دیتابیس و کلید API وارد این رکورد، audit، SSE، چت یا خروجی حافظه نمی‌شوند. رکوردهای اجراشده بعد از قطع برنامه به نتیجهٔ نامشخص علامت می‌خورند و خودکار بازپخش نمی‌شوند. خطا، ساخت تکراری یا حذف خودکار منابع را فعال نمی‌کند؛ منابع باقی‌مانده ممکن است هزینه داشته باشند. صفحهٔ نتیجه، مراحل و شناسه‌ها و امکان بررسی لاگ همان برنامه را دارد. ادامه/پاک‌سازی نیمه‌خودکار منابعِ نامشخص هنوز ارائه نشده است.

رمزگذاری محلی برای MVP تک‌کاربره است؛ master.key کنار ciphertext در `data/vault` نگه داشته می‌شود و باید با دسترسی سیستم‌عامل محافظت شود. در ویندوز ACL پوشه تعیین‌کننده است. این معماری جایگزین KMS یا secret manager چندکاربره نیست؛ نسخهٔ پشتیبان کامل data را محرمانه بدانید. Vite دسترسی HTTP به data را مسدود می‌کند؛ سرور production فقط dist را سرو می‌کند.

## محدودیت‌های صریح

- ساخت حساب لیارا و شارژ بانکی آن جزو API این محصول نیست. یک بار کلید حساب لازم است؛ مقدار آن از فرم امن قابل ذخیره است و ویرایش env لازم نیست.
- آماده‌سازی schema و migration خودکارِ مستقل پیاده‌سازی نشده؛ رفتار build/start پروژه مسئول migrationهای تعریف‌شده در همان سورس است. ایجاد سرویس دیتابیس به معنی ایجاد تمام جدول‌های برنامه نیست.
- برنامه‌های ناشناخته، monorepo پیچیده و پروژهٔ نیازمند Dockerfile همچنان باید بسته‌بندی صحیح داشته باشند.
- تغییرات env روی برنامهٔ دلخواه موجود، افزایش پلن، حذف سرویس و راه‌اندازی عمومی دیتابیس از این جریان در دسترس نیستند.
- دمو تمام مراحل هزینه‌زا را شبیه‌سازی می‌کند؛ فقط تحلیل و بسته‌بندی سورس واقعی است. اتصال واقعی و ساخت منابع پولی با حساب کاربر در این بررسی اجرا نشده است؛ مسیر API با provider شبیه‌سازی‌شده تست شده است.
